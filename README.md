# 3DProperty

사진·평면도와 치수 정보를 활용한 편집 가능한 3D 공간 모델링 프로젝트입니다.

**2026-11-01 공유 기준:** 민규님 홈·집들이 디자인, 재욱님 가구 파이프라인과 최신 좌표 기반 공간 모델을 통합한 코드입니다. 우리 집 기본값은 **112A 확장형**입니다. 112A 기본/확장과 168C 확장은 `archisketch-metric-v1`, 168C 기본은 `archisketch-details-v2`를 사용합니다. 211A 기본/확장은 별도 한 층 보기에서 168C와 연결됩니다. 공용 복도·엘리베이터 배치와 치수는 검토용 가정입니다.

공개 시연: https://cortex-design-preview-20261024.spunky-note-2434.chatgpt.site/ — 소스 푸시와 공개 사이트 배포는 별개입니다. 실행 경로·포함 자산·검증 방법은 [공유 코드 기준](#공유-코드-기준)을 참고하세요.

현재 서비스 홈과 지도·공간 뷰어는 연결되어 있으며 `3DProperty_GUI`는 별도 프로토타입입니다. `src/walkthrough`의 렌더링·배치 기능과 `apps/web/src/furniture.js`의 결과 검증을 재사용하는 구성을 권장합니다. 화면마다 모델·배치 상태를 복사하지 말고, 하나의 자산 ID·미터 단위 위치·회전 상태를 공유하도록 연결합니다. 실제 통합과 기존 앱 정리는 별도 PR에서 진행합니다.

7주차 우선순위와 역할은 [MVP 작업 목록](docs/week07-todo.md)에 정리합니다.

협업은 다음 순서를 권장합니다.

1. `main`은 팀원이 실행할 수 있는 통합 버전으로 유지합니다.
2. 작업 시작 시 최신 `origin/main`에서 `feat/<작업명>` 브랜치를 만듭니다. 미커밋 작업이 있는 폴더에서는 먼저 커밋하거나 별도 worktree를 사용합니다.
3. 자기 변경을 커밋하고 브랜치를 push한 뒤 PR로 합칩니다. PR에는 실행 방법, 검증 결과, 화면 캡처, 아직 연결하지 않은 기능을 적습니다.
4. `package.json`, 모델 메타데이터, 공통 JSON 규약처럼 여러 기능이 쓰는 파일은 PR에서 변경 영향을 함께 확인합니다. 공유 `main`에는 force push를 사용하지 않습니다.
5. 치수 근거가 달라지는 모델은 새 버전 폴더로 보관합니다. `node_modules`, 빌드 산출물, Blender 백업, 학습 가중치, 개인 자료는 커밋하지 않습니다.

## 웹 개발 시작하기

### Mac에서 H200의 최신 Studio 열기

서버의 최신 지도 서비스와 실내 모델을 보려면 **[open-studio.command](open-studio.command)** 파일 하나를 Mac에 저장하고 더블클릭합니다. 기존 SSH 설정의 `yj1-H200-kinamkim` 연결을 사용하며 요청될 때 비밀번호를 입력합니다. Mac에 Node.js나 모델 파일을 설치할 필요가 없습니다.

최초 한 번만 Mac 터미널에서 실행하면 바탕화면에 파일을 복사하고 실행 권한을 설정합니다.

```bash
scp \
  yj1-H200-kinamkim:/home/nas5/kinamkim/Repos/geonwoo/3DProperty/open-studio.command \
  ~/Desktop/open-studio.command &&
chmod +x ~/Desktop/open-studio.command &&
open ~/Desktop/open-studio.command
```

이후에는 바탕화면의 **open-studio.command**를 더블클릭합니다. SSH 연결과 지도·뷰어 서버 시작/재사용을 처리한 뒤 **지도에서 위치 선택** 화면을 엽니다. 아크로리버파크를 고르면 단지 3D → 동·층 → 2D 평면·측정 / 실내 3D로 이어집니다. 다른 위치는 준비 중 목업입니다. Mac 잠자기 등으로 연결이 끊겼다면 다시 더블클릭합니다. 실행 완료 후 터미널 창은 닫아도 됩니다. 이전 파일을 이미 받았다면 위 명령을 한 번 다시 실행해 갱신합니다.

기본 로컬 포트는 뷰어 **35173**, 지도 **35185**이며, 각각 사용 중이면 비어 있는 포트를 자동으로 선택하고 기억합니다. 구버전의 뷰어 포트·SSH 연결은 유지하고 지도 포워딩만 추가합니다. 실제 뷰어 주소를 `viewerUrl`, 지도 복귀 주소를 `serviceUrl`로 전달하므로 임의 로컬 포트도 연결됩니다. 포트가 바뀌면 이전 저장 배치는 이전 주소에 남습니다. 비밀번호는 SSH에서 직접 입력하며 실행 파일에 저장하지 않습니다.

종료가 필요하면 Mac에서 `bash ~/Desktop/open-studio.command --stop`을 실행합니다. 이 파일의 지도·뷰어 SSH 연결만 닫으며, 서버·Blender MCP·다른 사용자의 포트는 유지합니다. 서버 도우미는 `tools/start-remote-studio.sh`, 로그는 `runtime/dev/remote-studio.log`와 `remote-service.log`입니다. 서버가 이미 실행 중이면 재시작하지 않습니다. 새로 시작할 때는 가구 추론 API가 비활성인 웹 전용 모드입니다.

### Mac의 로컬 소스로 개발하기

기본 시작 화면은 **http://localhost:5185 (`apps/web`)의 지도**다. 루트와 `apps/web`에서 최초 1회 `npm ci` 후, 루트에서 **`bash start.sh`** 하나로 웹과 3D 뷰어를 실행한다. GPU 서버 API가 준비돼 있으면 SSH 터널도 켜서 이미지 측정을 연결하고, 서버가 없으면 이미지 미리보기·JSON 확인·3D 기능만 사용한다. 서버 API 실행과 SSH 설정은 [가구 측정 실행 안내](services/furniture_pipeline/README.md)를 따른다. 5173은 서비스 시작 화면이 아니라 3D 공간 뷰어다. 기존처럼 두 폴더의 `npm run dev`와 `npm run furniture:tunnel`을 수동 실행해도 된다. 수동 개발 실행의 API 설정과 별개로 `open-studio.command`는 새 서버를 웹 전용 모드로 시작하며 기존 서버의 설정은 바꾸지 않는다. 이후 API를 연결했다면 두 Vite 서버를 재시작한다. 명시한 `VITE_FURNITURE_MEASUREMENT_ENABLED=0/1`은 자동 감지보다 우선한다.

### 단지 → 세대 → 방 선택 및 꾸미기

`http://localhost:5185/`에서 지도 → 아크로리버파크 → 동·층 → 체험 평면으로 이동합니다. 5173의 기본 주소도 지도로 안내합니다. `?studio=1`, `?studio=0`, `?variant=...`처럼 명시한 기존 링크는 뷰어 직접 진입을 유지하며 상단 **지도에서 위치 찾기**로 서비스에 돌아옵니다. 아크로 외관은 OSM 윤곽·높이에 기반한 시각화이고 실제 층·호·타입 매핑은 미확인입니다. 네 실내 모델은 별도 체험 평면입니다. 임의 SSH 포트는 새 런처가 자동 연결하며 수동 연결은 [진입 주소 계약](docs/web-integration.md)을 참고하세요.

꾸미기 화면 왼쪽은 미터 좌표의 2D 평면, 오른쪽은 같은 상태를 사용하는 실시간 3D입니다. 소파·스툴·침대를 드래그/수치 이동하고 추가·회전·삭제할 수 있습니다. 벽/고정 집기/다른 가구와의 평면 겹침을 검사합니다. 조작 종료 후 보행 충돌 메시를 갱신합니다. 배치는 기본형/확장형별로 현재 브라우저에 저장·불러오기하며, 서버 저장이나 Blender로 편집 결과 역전송은 아직 없습니다. 1인칭 이동은 PC 키보드·마우스와 휴대폰·태블릿 터치를 지원합니다. 현재 네 평면에는 고정 주방·욕실 설비가 포함되며, 배치한 소파·테이블 및 112A 침대·서재 가구를 편집할 수 있습니다.

아래 `dimensioned-v3` 관련 문단은 이전 112A 모델의 이력입니다. 현재 웹 모델은 위의 치수 기반 갱신 문서를 따릅니다. 이전 모델은 `dimensioned-v3`로 보존합니다. 천장고 2.6m는 [ACRO 공식 안내](https://www.acro.co.kr/Posm_main.action?commonMap.CD_BIZ_LND=010366) 기준입니다. 문 개구부 높이 2.1m는 이번 모델의 설계 가정이며 실제 단지 문 규격으로 검증하지 않았습니다. [한샘 도어 카탈로그](https://image2.hanssem.com/event/doc/catalog/Hanssem_Door_2601.pdf)는 제품별로 제작 높이 범위를 안내하며 모든 문에 단일 높이가 적용되는 것은 아닙니다.

안방 매트리스는 킹 1670×2075mm([ACE K 규격](https://www.acebed.com/product/bed/mattress/view.do?detailsKey=24))를 유지하고 참고 배치도처럼 머리판이 서쪽을 향하도록 회전했습니다. 작은 방 1은 빈 방, 작은 방 2는 책상·의자로 바꿨습니다. 책상 120×60×74cm, 의자 외곽 54×55×85cm는 선택한 설계값이며 실측값이 아닙니다. 작은 방 방문 경첩 방향과 전면 발코니 창호를 참고 이미지에 맞춰 수정했고 발코니도 장소 목록에서 선택할 수 있습니다.

기존 17개 도면 치수 구간과 확장부 추정 범위를 유지하며 기본형 바닥 18개·확장형 바닥 14개의 경계가 v2와 동일함을 검사합니다. 가운데 작은 방은 기본형 2.458×2.593m, 확장형 약 2.458×3.08345m입니다. 도면 사이 구간은 보간, 확장은 추정 시나리오이므로 전체 건물 실측 일치를 의미하지 않습니다. 생성 명령은 `uv run --offline --python 3.11 --with bpy==4.5.3 python tools/blender/update_reference_revision.py`이며 결과·검사 기록·방 치수 CSV·모델에서 추출한 치수 SVG는 `assets/models/acro-river-park/112a/dimensioned-v3/`에 있습니다. 확장형 SVG는 독립적인 원본 치수 도면이 아닙니다. v1·v2와 `week-06-presentation` 태그는 보존합니다.

1인칭 기본값은 눈높이 1.60m, 충돌 몸체 지름 44cm, 머리 상단 1.72m, 가로 시야각 85°이며 수평으로 바라봅니다. **사람 크기 · 시점 · 화질**에서 눈높이·몸체 폭·가로 시야각을 바꿀 수 있습니다. **화면 크기 보정**은 실제 모니터 가로 길이와 눈–화면 거리로 투영각을 계산하며 기본 입력 32cm/60cm는 예시입니다. 화면 물리 크기와 브라우저 배율을 맞춰야 하며 양안시·실제 공간의 깊이 감각까지 재현하는 기능은 아닙니다. 기존 배치 저장값은 v2 키에 남겨두고 새 기본 배치는 v3 키에 저장합니다.


두 화면은 직접 링크로 연결됩니다. 이미지 업로드·치수 측정 뒤 고정 Blender 테스트 테이블을 GLB로 생성하여 웹 미리보기와 Studio 배치·이동·회전·저장/복원을 지원합니다. GPT API는 호출하지 않으며 사진 속 형태를 재현한 모델은 아닙니다. 서버 Blender 설치와 실행은 [실행 안내](services/furniture_pipeline/README.md), 두 웹 화면의 통합 기록은 [웹 연동 문서](docs/web-integration.md)를 참고하세요.

각 앱 폴더에서 `npm test`와 `npm run build`로 확인합니다. 브라우저 검사는 `npx playwright install chromium` 후 `npm run test:browser`로 실행합니다. 서비스 앱 브라우저 검사에는 5173 뷰어도 필요합니다. 비공개 S2 자료가 필요한 검사는 해당 환경 변수가 없으면 skip됩니다.
