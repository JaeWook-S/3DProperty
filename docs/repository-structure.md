# 레포 구조와 모델 버전 관리

## 지금 사용하는 구조

공유 가능한 결과 모델은 `assets/models/<단지>/<타입>/<버전>/<형태>/`에 둡니다. 예: `assets/models/acro-river-park/112a/dimensioned-v1/basic/`.

- 단지와 타입은 소문자 영문·숫자·하이픈으로 표기합니다.
- `basic`, `expanded`는 같은 치수 기준을 공유하는 형태 구분입니다.
- 단위 변경이나 도면 교체 등 기준이 바뀌면 `dimensioned-v2` 같은 새 버전을 추가합니다. 소규모 수정은 해당 버전의 Git 커밋으로 기록하고 검증 기록·미리보기·파일 해시를 함께 갱신합니다.
- 버전 폴더 README에 입력 근거, 가정값, 검증 범위, Blender 버전과 여는 방법을 적습니다.
- 원본 `.blend`를 편집 기준으로 삼고 GLB 등 내보내기를 추가할 때는 형태별 `exports/`에 둡니다. 반복 생성한 ZIP은 레포에 중복 보관하기보다 GitHub Release 첨부로 공유할 수 있습니다.

## 필요할 때 추가할 영역

`src/`는 웹·서버 코드, `tools/blender/`는 재현 가능한 모델 생성·내보내기 코드, `docs/`는 설계·실험 기록을 위한 위치로 사용할 수 있습니다. 이번 업로드에는 필요한 폴더만 생성했습니다.

회의 녹음·채팅·개인 계정 정보가 있는 자료는 별도 비공개 저장소에서 관리합니다. 원본 이미지나 도면을 공용 레포에 추가할 때는 공유 가능한 자료인지 확인하고 해당 모델 README에 연결합니다.

## 바이너리 파일

현재 Blender 파일은 각각 약 7MB이며 일반 Git으로 저장했습니다. 이 레포는 지금 Git LFS를 요구하지 않습니다. 대용량 모델이나 바이너리 수정 이력이 늘어나면 팀의 Git LFS 저장공간·다운로드 환경을 확인한 뒤 전환합니다. LFS 포인터만 남기고 원본 업로드가 빠지는 일이 없도록 설정 변경과 실제 파일 업로드를 함께 검증합니다.

`.blend1`, `.blend2` 등 자동 백업, 렌더 캐시, 임시 파일은 커밋하지 않습니다. 원본 `.blend`와 선택한 미리보기·검증 자료를 명시적으로 추가합니다.
