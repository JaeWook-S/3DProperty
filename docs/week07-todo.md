# 7주차 MVP 작업과 다음 순서

2026년 10월 8일 내부 회의 기준으로, 아크로리버파크 112A에서 일반 사용자가 공간을 둘러보고 가구를 배치하는 MVP를 먼저 완성한다. 기존 도면 안에서 고르는 추천 컨셉을 추가하고, 이미지 입력부터 가구 생성·배치까지 연결한다. 치수 추정의 정량 개선과 인하대 도면 준비는 이어서 진행한다.

담당 이름은 기존 팀 역할과 회의의 작업 배분을 함께 반영했다. 이번 S1 구현 순서는 최신판 공유 → 미니맵 → 112A 도면·치수 재검증 → 엘리베이터/반입 경로다. S2/S3 코드를 대신 수정하거나 각자의 결과를 완료로 표시하지 않는다.

## 이번 회의에서 좁힌 범위

- 추천 컨셉은 먼저 현재 112A 도면 안에서 구현한다. 임의의 인테리어 사진을 다른 도면에 자동 매핑하는 기능은 후속 과제다. (14:39–17:20)
- 가구 치수 추정은 유지한다. 모델·데이터를 조사하고 공통 표본에서 정량적인 개선을 확인하되 MVP의 모든 기능을 학습 완료까지 기다리게 하지 않는다. (18:24–22:29)
- 모바일 조이스틱은 이미 공유된 구현을 통합한다. 모바일을 위한 추가 확장은 이미지 입력·가구 연동보다 후순위다. (21:09–21:40)
- 홈투어 영상·이미지 생성은 부가 기능으로 미룬다. (15:47)
- 엘리베이터 반입이 어려울 때 창문 경로도 검토하는 아이디어가 나왔다. 실제 승강기·복도·출입구·창호 치수와 운반 방향 없이 반입 가능 여부를 확정하지 않는다. (08:22–09:36)

## 이미 구현한 범위

- 112A 기본형·확장형 v3와 미터 좌표, 참고 이미지에 따른 빈 방·서재·안방 배치.
- 예시 단지의 여러 동·층 선택과 A동 22층 시연 세대 연결.
- 실시간 2D/3D 편집, 겹침 허용/제한 토글과 배치 경고, 하단 편집 도구.
- 눈높이·몸체 폭·시야각·화면 크기 보정, 발코니 선택.
- 공식 단지 사진을 사용하는 참고 외부 배경. 실측 단지 배치나 실제 22층 조망은 아니다.
- `origin/main`의 모바일 입력 구현: `83eafbb`, 병합 `3446aaa`. 통합 후 검사는 아래 기록에서 구분한다.

## 공유와 검증

- 발표 기준은 `week-06-presentation` 태그(`72b8007`)에 보존한다.
- 10월 9일 사용자 요청에 따라 최신 통합판과 미니맵을 `main`에 반영한다. `feat/post-week06-improvements`는 이번 통합 작업 기록이며 이후 기본 개발 기준은 `main`이다. 팀원의 커밋과 저자 정보를 유지하며 force push하지 않는다.
- 10월 6일 v3 기준 단위 17개·브라우저 8개·빌드가 통과했다. 이 기록은 모바일 통합 이후의 검사를 대신하지 않는다.
- 실제 Mac/iPhone의 성능과 조작감은 별도 확인이 필요하다. 서버 Chromium의 터치 에뮬레이션은 실기기 검증이 아니다.

### 10월 9일 최신판 통합 검증

`origin/main`의 모바일 구현을 v3 스튜디오와 병합했다. 단위 25개, 브라우저 9개(모바일 4·기존 뷰어 4·단지/편집 화면 1), 빌드가 통과했다. PC 마우스 잠금과 터치 이동을 모두 확인했고, 모바일 입력 모듈 및 모바일 검사 원본은 팀원 커밋과 동일하다. 기존 500KB 번들 경고는 남아 있다.

### 10월 9일 미니맵 구현과 검증

현재 위치·시선 방향·현재 방을 둘러보기 미니맵에 표시한다. 기본형/확장형의 미터 좌표를 그대로 사용하며, 가구 편집 결과와 경첩문의 개폐 상태를 반영한다. PC는 `M`, 모바일은 버튼으로 접거나 펼친다. 모바일 가로 화면은 접힌 상태로 시작하고, 지도 위 드래그가 기존 시선 조작을 방해하지 않도록 했다.

단위 28개, 빌드, 미니맵 브라우저 3개가 통과했다. PC 위치·방향·편집 반영·평면 전환, 모바일 세로의 이동·시선·접기, 모바일 가로의 버튼 겹침을 확인하고 화면 4장을 검토했다. 위의 통합 브라우저 9개는 미니맵 추가 전 검사이며 이번 3개와 실행 시점을 구분한다. 실기기 성능은 측정하지 않았다.

10월 9일 추가 비율 피드백에 따라 다음 S1 작업을 W7-02A로 조정한다. 현재 모델은 선택한 17개 치수의 제약과 나머지 구간의 보간을 사용하며, 확장부는 별도의 원본 치수 없이 추정했다. 같은 도면의 숫자와 모델이 일치하는 것과 실제 건물의 정확도 검증은 다르다. 원본 치수 도면을 확보하고 방·문·복도·확장 깊이를 재검증한 뒤 W7-03으로 진행한다.

### 10월 9–10일 추천 컨셉·창밖 풍경 (W7-06, W7-07)

`feat/recommended-concepts`에서 구현했다. 상단 탭을 **둘러보기 / 꾸미기 / 컨셉 보기**로 나누고, 장소 선택에 처음 화면인 **전체 보기**(2D 평면 + 3D)를 추가했다. 컨셉 보기 탭은 항상 가족 구성 목록에서 시작하며 가족 구성·분위기로 컨셉 4개(패밀리 라운지, 키즈 플레이 하우스, 신혼 갤러리 라운지, 재택 라이브러리 스튜디오)를 추천한다. 적용해도 목록에 머물고, 카드에서 색감을 바꾸며 **자세히**를 눌렀을 때만 상세 점검으로 넘어간다. 둘러보기 중에는 화면 아래 테마 막대(PC 숫자키 1–5, C) 또는 터치용 **테마** 버튼으로 같은 위치에서 컨셉과 색감을 바꾼다. 바뀐 가구가 몸과 겹치면 같은 방 안의 가까운 빈 곳으로 옮긴다.

컨셉 가구는 방 경계 기준 규칙으로 현재 평면에 맞춰 계산하며, 기본형·확장형 모두 겹침·경계·문 개방 경고 없이 놓인다. 기본형은 주방 폭 때문에 2인 식탁으로 바꾸고 상세 화면에 표시한다. 자세한 기준은 [추천 컨셉 배치](recommended-concepts.md)에 있다.

창밖은 10월 10일 피드백에 따라 방위 시뮬레이션을 삭제하고 공식 단지 사진을 기본으로 유지했다. 직접 찍은 360° 사진으로 바꿔 보는 기능만 남겨 실제 조망 자료를 넣는 흐름을 시험한다. 화면 문구에서 ‘예시’ 표현을 정리했다. 실제 조망 단계는 [창밖 풍경](window-view.md)에 정리했다.

공용 코드 변경: `studio.js`에 꾸미기 탭 이름, 장소 선택의 전체 보기, 확장 모듈 훅을 추가했다. `main.js`에는 가구가 바뀐 뒤 몸을 빈 곳으로 옮기는 `settle`, 지정 시점에서 걷기 시작하는 `standAt`, 위치를 유지한 채 다시 걷는 `resume`를 넣었다. `layout.js`의 60cm 여유 점검은 같은 방 가구로 한정하고 바닥 러그·매트는 겹침 경고에서 제외했다(기존 기본 배치의 벽 너머 소파↔침대 오경고도 사라짐). `staging-assets.js`에 템플릿 등록·배치 함수, `location.js`에 사진 배경 그룹 반환을 추가했다.

검증(10월 10일): 단위 36개, 새 브라우저 5개(탭·전체 보기·추천·적용·색감·상세, 기본형·저장 복원, 공유 링크와 걸으며 테마 전환, 휴대폰 시트와 테마 버튼, 창밖 360° 사진), 빌드 통과. 기존 브라우저 17개는 macOS headless Chromium이 Pointer Lock을 거부하므로 Pointer Lock 대체 스크립트로 실행해 모두 통과했다. 실제 iPhone·태블릿 성능은 측정하지 않았다.
