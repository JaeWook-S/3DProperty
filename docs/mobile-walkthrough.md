# 휴대폰·태블릿 공간 체험 (터치 조작)

PC와 같은 공간 뷰어(5173)를 휴대폰·태블릿에서도 1인칭으로 걸어볼 수 있습니다. 별도 페이지가 아니라 같은 주소에서 입력 방식만 바뀌며, 모델·치수·문·마감·조명·화질 설정과 스튜디오(`?studio=1`)를 그대로 사용합니다.

## 실기기에서 열기

Mac과 휴대폰을 같은 Wi-Fi에 연결하고 저장소 루트에서 실행합니다.

```bash
npm run dev:mobile
```

터미널에 표시되는 `Network: http://<Mac의 IP>:5173/` 주소를 휴대폰 브라우저에서 엽니다. 스튜디오는 같은 주소에 `?studio=1`을 붙입니다. macOS가 node의 수신 연결 허용을 물으면 허용해야 합니다. `dev:mobile`은 개발 서버를 같은 네트워크의 다른 기기에 공개하므로 신뢰할 수 있는 네트워크에서만 사용합니다. 기존 `npm run dev`는 지금처럼 127.0.0.1에만 열립니다.

원격 서버에서 개발 서버를 실행하는 경우 SSH 포트 전달은 PC에만 적용되므로, 휴대폰이 접속할 수 있는 주소가 따로 필요합니다. `npm run build` 결과(`dist/`)를 정적 HTTP(S) 서버에 올려도 같은 터치 조작이 동작합니다.

PC에서 터치 조작을 미리 보려면 주소에 `?input=touch`를 붙입니다. 마우스로 방향키와 시선을 끌어 조작할 수 있습니다. `?input=mouse`는 터치 기기에서도 기존 마우스 잠금 방식을 사용합니다.

## 조작

**공간에 들어가기**를 손가락으로 누르면 터치 조작, 마우스로 누르면 기존 PC 조작(마우스 잠금)으로 시작합니다. 터치와 마우스를 함께 쓰는 노트북·태블릿에서는 시작 버튼을 누른 입력으로 정합니다. Pointer Lock을 지원하지 않는 브라우저도 터치 조작으로 시작합니다.

| 위치 | 동작 |
| --- | --- |
| 왼쪽 아래 방향키 | 위로 밀면 앞으로, 아래는 뒤로, 좌우는 옆으로 걷습니다. 미는 만큼 빨라지며 끝까지 밀면 PC의 W 키와 같은 1.20 m/s입니다. 가운데 12%는 무시해 손가락을 올려두기만 해서는 움직이지 않습니다. |
| 방향키 주변 | 왼쪽 아래 영역 어디든 엄지를 대면 방향키가 엄지 아래로 옮겨와 그 자리에서 시작합니다. 손을 떼면 즉시 멈추고 제자리로 돌아갑니다. |
| 그 밖의 화면 (오른손) | 끌어서 둘러봅니다. 오른쪽으로 밀면 오른쪽으로 돌고 아래로 밀면 아래를 봅니다. 화면 짧은 변만큼 밀면 약 138° 돕니다. 위아래 각도 제한은 PC와 같습니다. |
| 두 손 동시 | 왼손으로 걸으면서 오른손으로 방향을 바꿀 수 있습니다. |
| 오른쪽 아래 버튼 | 화면 가운데 점이 2.2m 안의 문을 향하면 "가운데 침실 문 열기"처럼 표시됩니다. 누르면 여닫힙니다. |
| 화면 탭 | 짧게 탭한 위치의 가까운 문을 여닫습니다. 끌기와 구분하기 위해 10px·0.35초 안의 터치만 탭으로 봅니다. |
| 오른쪽 위 | **둘러보기 종료**로 설정 패널에 돌아갑니다. 전체 화면 버튼은 지원하는 브라우저(Android Chrome, iPad Safari 등)에만 표시되며 iPhone Safari에는 없습니다. |

키보드를 연결한 태블릿에서는 터치 조작 중에도 WASD·E가 동작하고 Esc로 종료합니다. 다른 앱으로 전환하거나 시스템 제스처로 터치가 취소되면 방향키 입력을 즉시 해제합니다. 스튜디오의 **이곳에서 둘러보기**도 같은 조작을 사용하며, 걷는 동안 헤더를 숨기고 3D 화면을 전체로 넓힙니다.

## 구조와 기존 코드와의 경계

모바일 입력은 `src/mobile/`에만 둡니다. 이동 속도·충돌·문·렌더링은 PC와 같은 코드를 공유하므로 미터 스케일과 충돌 기준이 같습니다.

| 파일 | 역할 |
| --- | --- |
| `src/mobile/touch-input.js` | DOM 없는 계산: 방향키 입력과 dead zone, 시선 감도와 상하 제한, 탭 판정 |
| `src/mobile/touch-walk-controls.js` | `TouchWalkControls`. PointerLockControls와 같은 형태(`lock()`/`unlock()`, `isLocked`, `lock`·`unlock`·`change` 이벤트)로 터치 레이어·멀티터치·입력 방식 판별을 담당 |
| `src/mobile/touch-walk.css` | 터치 레이어, 터치 보행 중 화면 배치, 터치 기기용 패널 안내, 가로 휴대폰 패널. 터치 보행 상태나 터치 기기 조건에서만 적용 |

기존 파일의 연결 지점은 다음과 같습니다.

- `src/walkthrough/main.js`: `TouchWalkControls` 생성, 시작 버튼과 스튜디오 방 이동에서 입력 방식 선택(`startWalking`), 이동 루프에 방향키 입력 합산(`movementVector`가 키보드와 합친 값도 보행 속도로 제한), 문 버튼 표시(`setAction`), 해제 시 두 조작 모두 해제(`release`). 테스트 상태에 `touchWalking`, `touchInput`, `yaw`, `pitch`를 추가했습니다.
- `src/walkthrough/studio.js`: 기기에 맞는 조작 안내 문구.
- `index.html`: 터치 기기에서 키보드 안내 대신 보이는 안내 한 줄.
- `package.json`: `dev:mobile` 스크립트.

## 검증

```bash
npm test
npx playwright test tests/mobile-walkthrough.browser.js
```

- 단위 검사 19개(기존 11 + 터치 계산 8): 방향과 dead zone, 아날로그 세기, 끝까지 민 방향키가 1.20 m/s이고 키보드와 겹쳐도 더 빨라지지 않는지, 시선 회전량·상하 제한, 탭 판정.
- 브라우저 검사 4개, Chromium 터치 에뮬레이션에 CDP로 실제 터치 이벤트를 보냈습니다.
  - 휴대폰 세로 390×844: 방향키 전진과 손 뗀 뒤 정지, 방향키 옮겨 시작, 터치 취소 시 해제, 시선 회전량과 상하 제한, 두 손가락 동시 조작, 탭과 끌기 구분, 문 버튼과 문 탭으로 여닫기, 종료 후 패널 복귀.
  - 휴대폰 가로 844×390: 패널의 시작 버튼이 스크롤 없이 보이고, 방향키·문 버튼·상단 버튼·방 이름이 서로 겹치거나 화면 밖으로 나가지 않음.
  - 태블릿 1180×820 스튜디오: 방 둘러보기 시 전체 화면 터치 조작, 종료 후 스튜디오 화면 복귀.
  - PC: 마우스 클릭은 기존 마우스 잠금 경로를 사용하고 터치 레이어가 나타나지 않음. `?input=touch`에서 마우스로 방향키·시선 조작.
- 실제 iPhone·Android 기기, Safari, 실기기 FPS는 아직 확인하지 않았습니다. 소프트웨어 WebGL(SwiftShader) 결과는 실기기 성능을 뜻하지 않습니다.

## 한계와 다음 단계

- 모바일 GPU에서 끊기면 **시점 · 화질 설정 → 화면 품질 → 가벼움**을 선택합니다. 기본 화질은 PC와 같게 유지했습니다.
- 자이로·VR, 시선 감도 설정 화면은 없습니다. 감도는 `touch-input.js`의 `LOOK_RADIANS_PER_SHORT_SIDE`입니다.
- 패널 화면에서 두 손가락으로 페이지를 확대한 채 시작하면 터치 컨트롤 위치가 어긋날 수 있습니다. 원래 크기로 되돌린 뒤 시작합니다.
- 서비스 앱(`apps/web`)의 "공간 이동은 PC에서 지원" 안내와 해당 검사는 이번 범위에서 바꾸지 않았습니다.
