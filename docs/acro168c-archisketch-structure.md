# 168C 아키스케치 좌표 기반 구조 검토

2026-10-12. 기본형과 확장형을 각각 BLEND·GLB로 생성했다. 이번 단계는 방 경계·발코니·문·창의 구조 검토다. 기존 `finishes-v1` 모델은 유지하며, 새 기본형·확장형도 메인 스튜디오와 서비스 웹에서 선택할 수 있다.

- `http://127.0.0.1:5173/acro168c-review.html?variant=expanded`

SSH 로컬 포트가 다른 경우 기존 포트를 유지하고 경로만 바꾼다.

## 사용한 원본과 해석

확장형은 현재 아키스케치 확장형 프로젝트를 다시 읽었다. 이름이 기본형인 기존 프로젝트도 현재는 확장형과 동일한 구조를 담고 있어 기본형 입력으로 쓰지 않았다. 기본형은 2026-10-12 05:07:34 갱신 시점의 최초 보관본을 사용했다. 이 원본은 32개 영역과 27개 개구부를 포함하며 침실 앞 긴 발코니와 거실 동쪽 발코니가 구분되어 있다.

두 원본은 AisideProject의 `references/week-07/acro-river-park/archisketch/168C/{basic,expanded}/modeling-source-*/`에 별도로 보존했다. 생성 명세에 원본 경로, 갱신 시점과 해시를 기록했다. 아키스케치 클라우드 프로젝트는 수정하지 않았다.

- 평면 좌표는 원본 mm를 m로 변환하고 원점만 평행이동했다. 방을 직사각형으로 단순화하거나 집 전체를 면적에 맞춰 확대·축소하지 않았다.
- 천장 아래면은 기본형·확장형 모두 사용자 지정 **2.50m**다.
- 일반 여닫이 문짝은 **0.80 × 2.40m**, 문틀용 개구부는 임시 여유를 더한 0.84 × 2.42m다.
- 확장형 침실 2·3 창틀은 **1.60 × 1.40m**, 창 부분은 **1.40 × 1.20m**다. 거실 큰 창 부분은 **3.40 × 1.80m**다. 이 값은 전체 창 영역이며 미닫이문을 열었을 때의 유효 통과 크기를 뜻하지 않는다.
- 벽 중심선과 원본 벽 두께는 MCP 요약에 없어 방 경계 사이 간격과 바깥 0.20m 띠를 이용해 벽체를 추론했다. 외벽 0.20m, 문틀 여유, 미측정 창호·창턱 높이는 실측 확정값이 아니다.
- 도면의 비사용 공간은 바닥과 구분된 천장 높이의 구조체로 막았다. 이름이 없는 일부 영역은 도면을 대조하여 주방 팬트리, 안방 발코니·부속 공간, 현관 수납으로 분류했다.
- 주방 팬트리 서쪽 출입구, 안방 발코니의 거실 쪽 차단, 거실·안방 발코니 미닫이 형상을 반영했다. BLEND/GLB에는 닫힌 문짝을 보존한다. 웹에서 해당 메쉬에 개폐 동작을 연결하며, 경첩 위치와 개폐 방향은 원본에 없어 임시 설정임을 표시한다.

## 원본에서 남은 검토 항목

1. 기본형·확장형 원본의 방 폭이 서로 다르다. 침실 1의 최대 경계 폭은 3.648m와 3.743m, 침실 2는 2.686m와 2.744m, 침실 3은 3.165m와 3.297m다. 이는 **원본 좌표 차이**이며 독립 실측 오차 판정이 아니다. 안쪽 요철·기둥 때문에 최대 폭과 가구 배치에 쓸 수 있는 직사각형 폭도 구분해야 한다.
2. 확장형 침실 2에는 X/Z 위치가 같고 높이만 다른 창 두 개가 있었다. 사용자 지정 치수의 창 하나로 구성하고 중복 원본을 기록했다.
3. 확장형 주방 팬트리와 거실 발코니 사이의 미닫이문 한 개는 원본 위치가 양쪽 유효 경계를 벗어나 있어 모델에서 보류했다. 거실에서 발코니로 나가는 주 출입구는 별도로 유지했다.
4. 위생기구, 붙박이장, 주방 수납장 상세 및 사진 기반 마감은 이번 구조 버전에 옮기지 않았다. 샤워부스 등은 구조 확인 후 복원할 다음 단계다. 기존 마감 버전에 있던 집기를 새 구조에 맞춰 재배치해야 한다.

## 파일과 재현

- 생성기: `tools/blender/build_acro168c_archisketch.py`
- 입력 명세: `tools/blender/specs/acro168c-{basic,expanded}-archisketch-v1.json`
- 독립 검사: `tools/blender/verify_acro168c_archisketch.py`
- 결과: `assets/models/acro-river-park/168c/archisketch-structure-v1/{basic,expanded}/`
- 각 결과 폴더: BLEND, GLB, `top-view.png`, `isometric.png`, `model-info.json`, `verification.json`
- 비교표: 상위 폴더의 `room-comparison.csv`, `comparison.json`
- 검토 화면: `acro168c-review.html`, `src/model-review/`

```sh
uv run --python 3.11 --with bpy==4.5.3 --with shapely==2.1.2 python tools/blender/build_acro168c_archisketch.py
uv run --python 3.11 --with bpy==4.5.3 --with shapely==2.1.2 python tools/blender/verify_acro168c_archisketch.py
```

재생성은 저장소의 명세를 사용한다. 독립 검증은 명세에 기록된 AisideProject 원본 스냅샷도 필요하다. `--variant basic` 또는 `--variant expanded`로 한 타입만 선택할 수 있다. `--skip-render`는 PNG 생성만 생략한다.

## 검증 결과와 다음 단계

기본형 304개, 확장형 282개 저장 파일 검사를 통과했다. 실제 방 바닥 메쉬와 원본 다각형의 최대 경계 차이는 각각 약 0.00000063m, 0.00000078m로 부동소수점 수준이다. BLEND와 다시 가져온 GLB의 메쉬 경계·분류도 일치했다. 이는 원본 좌표의 전송 정확도 검증이며 현장 치수 정확도를 입증하지 않는다.

브라우저에서는 두 실제 GLB 로드와 왕복 전환, 공간 선택, 보기 조작, BLEND 다운로드, 390px 화면의 가로 넘침 없음, JavaScript 오류 없음을 확인했다. Linux Chromium/SwiftShader 검사이며 Mac Safari와 실제 모바일 성능 검증은 아니다. 캡처 및 검증 기록은 AisideProject의 `realestate-spatial-ai/experiments/outputs/acro168c-archisketch-v1/`에 있다.

다음 단계는 원본 간 치수 차이와 보류 개구부 검토, 기존 샤워부스·주방·붙박이장 디테일 이식, 사진 기반 마감 적용이다.

## 메인 웹 연결 — 2026-10-12

스튜디오의 단지/세대 선택과 평면 선택, 일반 뷰어 및 5185 서비스 첫 화면에 두 모델을 추가했다.

- 기본형: `http://127.0.0.1:5173/?studio=1&variant=168c-basic-archisketch`
- 확장형: `http://127.0.0.1:5173/?studio=1&variant=168c-expanded-archisketch`
- 후속 갱신에서 네 가지 평면 모두 좌표 기반 구조로 통일했다. 이전 마감 모델 파일은 보존하되 웹 선택에서 제외하며, 기존 링크는 최신 구조로 연결한다. [현재 모델 기준](coordinate-models.md)을 따른다.

`archisketch-model.js`가 저장된 `model-info.json`의 다각형과 치수를 웹 형식으로 연결한다. 원본 GLB/BLEND는 재생성하거나 확대·축소하지 않는다. 방 선택과 미니맵, 1인칭 이동, 충돌, 가구 추가·이동·저장·복원을 지원하며 저장 키는 모델별로 분리한다. 비정형 벽의 미니맵은 큰 사각형으로 덮지 않고 실제 메쉬의 높이 1m 단면을 사용한다.

닫힌 자세로 내보낸 문을 처리하는 `exportedPose: closed`를 기존 문 어댑터에 추가했다. 기본형 19개, 확장형 15개 출입구에 동작을 연결한다. 두 공간을 잇는 미닫이문은 한쪽 패널을 이동하며, 외부로 바로 연결되는 유리창은 고정한다. 좁은 수납공간 미닫이문의 유효 통과 폭은 별도 검토가 필요하다. 문 방향은 현장 확인값이 아니며 배치 경고도 이 가정을 따른다.

새 모델은 상세 마감 전 구조본이므로 마감 선택은 원본으로 고정하고 조명 설정은 사용할 수 있게 했다. 상세 가구는 기본으로 들어 있지 않으며 꾸미기에서 추가할 수 있다. 서비스의 미리보기는 해당 구조 모델 렌더 이미지다.

검사 코드: `tests/archisketch-model.test.js`, `tests/archisketch.browser.js`. 실제 GLB 바닥 경계, 방 시작 위치, 닫힌 문 충돌·열린 문 통과, 웹 모델 전환과 저장 분리, 서비스 링크 및 미리보기를 검사한다. Linux Chromium/SwiftShader 결과이며 실제 Mac/iPhone 성능을 의미하지 않는다.

이번 웹 연결 검증: 관련 단위 검사 18/18, 실제 브라우저 4/4(신규 3 + 기존 168C 문 회귀 1), 뷰어·서비스 빌드 모두 통과했다. 두 모델의 BLEND/GLB 4개 해시가 생성 기록과 일치한다. 캡처 4장과 `verification.json`은 AisideProject의 `realestate-spatial-ai/experiments/outputs/acro168c-archisketch-v1/web-integration-20261012/`에 보관했다.

## 2026-10-21 — 168C 내부 디테일 및 동선 보완

현재 웹은 기본형·확장형 모두 `archisketch-details-v2`를 사용한다. 저장된 아키스케치 방 폴리곤과 문·창의 위치/폭/높이, 벽·외곽 프레임, 제외 공간을 유지하고 기존 `archisketch-interiors-v1` 위에서 집기와 개폐 방식을 보완했다. 천장 2.50m, 일반 문짝 0.80×2.40m, 보행체 기본 폭 44cm와 눈높이 1.60m를 유지한다. 좌표 전사 검증이며 현장 실측 정확도를 인증한 결과는 아니다.

VR 참조 17장과 미니맵을 검토한 기록은 `runtime/interior/2026-10-21-168c-details/reference-review.json`이다. 제공된 VR은 확장형이므로 기본형의 집기·마감은 기본형 원본 구조에 맞춘 적용이다. VR 치수 오버레이의 끝점이 확인되지 않은 길이로 집 전체를 늘리거나 줄이지 않았다. 원본 VR 이미지를 제품 GLB에 삽입하지 않았다.

- 기본형 주방 발코니 문을 막던 가로 싱크대를 제거하고 서쪽 조리대에 싱크를 통합했다. 확장형은 창 아래 싱크와 서쪽 부속실 입구를 유지하고 낮은 수납장·선반·배수구를 보완했다.
- 주방 상부장은 후드 주변을 분리하고, 오븐·수전·실제로 파인 싱크볼을 추가했다. 아일랜드/냉장고 배치는 통로를 확보하는 설계안이며 실측 가구 치수로 표시하지 않는다.
- 화장실 1은 북쪽 벽, 안방 욕실은 남쪽 벽을 기준으로 세면대·변기·거울을 재배치했다. 욕조와 세면볼은 열린 내부 형상을 갖는다. 샤워 고정 유리와 진입 공간은 구현했으나 별도로 닫히는 샤워부스 문은 아직 없다.
- 드레스룸 깊은 옷장·화장대·거울, 얕은 수납장, 걸레받이를 보완했다. 기존 소파 제품 규격은 유지하고 거실 테이블은 높이 45cm의 설계값으로 조정했다.
- 좁은 미닫이문은 각 타입 3곳에 전면 열림을 위한 표면 슬라이딩 방식을 제안했다. 개구부 폭은 유지했으며 실제 시공 하드웨어는 미확인이다. 움직이는 중앙 프레임과 고정 유리는 별도 레일에서 겹치지 않는다. 안방 발코니 수납실 문은 안쪽으로 열려 발코니 접근 동선과 겹치지 않게 했다.

모델 경로는 `assets/models/acro-river-park/168c/archisketch-details-v2/{basic,expanded}/`이며 각각 BLEND, GLB, model-info 및 검증 JSON이 있다. `refine_168c_details.py`가 재생성기, `verify_168c_details.py`가 독립 저장 파일 검사기다. 실행 환경은 `uv run --offline --python 3.11 --with bpy==4.5.3 --with shapely==2.1.2 python tools/blender/<script>.py`이다. 이전 v1 모델과 기존 도움 함수가 저장소에 있어야 한다.

검증: 저장 파일 독립 검사 기본형 867/867, 확장형 862/862. 실제 웹 충돌 엔진에서 50cm 폭으로 출입구 32곳의 닫힘 차단·열림 통과와 거실에서 각 공간을 잇는 32경로의 왕복 보행을 확인했다. 여닫이문 16곳은 5도 간격의 0~90도 회전 투영 검사에서 가구·벽 간섭이 없었다. 이 결과는 원형 보행체와 검사한 경로의 검증이며 가구 운반, 모든 체형, 실기기 FPS를 검증한 것은 아니다. `tests/168c-details.browser.js`와 `tools/blender/specs/acro168c-details-v2-circulation.json`으로 재현한다.

S3는 실제 활성 경로에서 112A/168C 네 모델의 로딩·도식·둘러보기 전환과 빌드를 확인했다. `runtime/interior/2026-10-21-168c-activation/verification.json` 참고. 새 웹 조명/PBR 세트는 적용하지 않았으며 Blender 검토용 조명만 별도로 보완했다. 이 작업은 커밋·푸시·배포를 포함하지 않는다.
