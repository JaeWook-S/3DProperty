# 168C 확장형 모델 제작 단계

현재 추가 검토본은 [아키스케치 좌표 기반 기본형·확장형](acro168c-archisketch-structure.md)이다. 두 타입의 BLEND·GLB와 별도 비교 화면을 만들었으며 기존 스튜디오의 마감 버전은 유지한다.

현재 웹과 Blender에 연결한 최신 버전은 [finishes-v1 재질·웹 연결](acro168c-finishes-web.md)이다. 구조는 [v2 주방·발코니 보정](acro168c-structural-v2.md)을 유지한다. 웹에서 112A 기본형·확장형과 168C 확장형을 선택할 수 있다. 아래 내용은 첫 구조 초안 당시의 기록이며, v0·v1·v2 산출물도 보존했다.

2026-10-12: **1단계 구조 검토용 초안 생성**. 기존 112A 모델과 웹 타입 선택은 변경하지 않았다.

## 단계와 현재 결과

1. **구조 초안 — 생성 완료, 실측 검증은 미완료.** 아래쪽 가로·왼쪽 세로 치수선을 임시 기준으로 벽, 문, 창, 발코니를 구성했다. 사용자가 지정한 천장고·문짝·창 크기를 실제 저장 메쉬에서 검사했다.
2. **구조 보정 — 다음 단계.** 도면 치수선 끝점과 벽 중심/안쪽 기준, 침실 깊이, 붙박이장 범위, 문 방향, 미측정 개구부를 비교 자료로 확인한다. 도면과 VR의 서로 다른 기준을 억지로 같은 수치에 맞추지 않는다.
3. **웹 연결.** 검토한 168C를 기존 112A와 별도 타입으로 추가하고 방 선택, 눈높이·보행 속도, 문 상호작용·충돌을 확인한다. 현재 GLB는 구조 파일이며 아직 실행 중인 앱에 연결하지 않았다.
4. **재질·조명·디테일.** VR 미니맵과 시선 방향으로 캡처를 방·벽면에 대응시키고 천장 몰딩, 붙박이장, 바닥, 벽·창호 마감을 보강한다.
5. **가구 배치와 이동 여유.** 모델 치수와 사용 가능한 공간을 따로 평가한다. 창 전체 폭을 창을 열었을 때의 유효 개방폭으로 간주하지 않는다.

스크린샷은 1단계에서도 구조·개구부·벽 돌출 확인에 사용한다. 색·질감 재현은 구조를 보정한 다음에 한다. 가구나 마감재가 구조 오류를 가리지 않게 단계별 결과를 분리한다.

## 파일

- 설정: `tools/blender/specs/acro168c-expanded-dimensions.json`
- 좌표·벽·개구부 초안: `tools/blender/specs/acro168c-expanded-layout-v0.json`
- 생성기: `tools/blender/build_acro168c_structure.py`
- 독립 저장/변환 검사: `tools/blender/verify_acro168c_structure.py`
- 결과: `assets/models/acro-river-park/168c/structural-v0/expanded/`
- 내부 비교 자료: 인접 AisideProject의 `realestate-spatial-ai/experiments/outputs/acro168c-structural-v0/comparison.html`

내부 비교 HTML은 참고 이미지를 포함한다. 공개 모델에는 원본 스크린샷 또는 그 텍스처를 넣지 않았다.

## 재현

```sh
uv run --python 3.11 --with bpy==4.5.3 python tools/blender/build_acro168c_structure.py
uv run --python 3.11 --with bpy==4.5.3 python tools/blender/verify_acro168c_structure.py
```

처음 실행할 때 bpy 및 의존성 다운로드가 필요하며, 캐시 후에는 `uv run --offline`도 가능하다. Blender MCP 연결은 서버 생성에 필요하지 않았다.

## 단위와 모델 구조

- Blender 단위 1 = 1m. 평면 좌표 `(x, y)` → Blender `(x, -y, 높이)` → glTF `(x, 높이, y)`.
- BLEND에서 `05_Ceiling` 안의 천장 객체는 검토를 위해 숨김 상태다. GLB에는 천장도 포함되며 `component=ceiling`으로 식별한다.
- 바닥과 모든 벽, 창, 열린 문짝을 포함한다. 가구, 위생기구, 상세 창짝·개폐장치와 구조 보강/시공 상세는 미포함이다.
- 문짝은 현재 열린 상태의 정적 메쉬다. `openings.json`에 힌지·회전·객체명이 있으나 웹 문 동작은 아직 구현하지 않았다.
- 색으로 구분한 방 영역과 텍스트는 BLEND 검토용이며 GLB에서는 제외했다.
- 위쪽 렌더는 문·창 위 인방만 일시적으로 숨긴 설명용 이미지다. 저장 파일에서 인방은 유지된다.

## 지정 치수와 초안값의 구분

천장 아래면 2.50m, 일반 문짝 0.80×2.40m, 침실 2·3 창틀 바깥 1.60×1.40m 및 창 부분 1.40×1.20m, 거실 창 1의 창 부분 3.40×1.80m를 적용했다. 거실 창 1의 바깥 프레임 3.60×2.00m는 VR 측정 그림을 참고했다.

외벽 180mm, 내벽 120mm, 문 개구부 840×2420mm, 창 하단 높이와 미측정 창은 초안값이다. 문짝과 창 전체 규격은 통행 유효 치수가 아니다. 거실 창 2의 3.1/3.2m 차이는 해결되지 않았고 임시 표시 형상만 3.2m로 만들었다.

기준 치수선은 아래 `[3.840, 2.860, 3.460, 8.840, 1.500]m`, 왼쪽 `[3.340, 0.675, 1.750, 3.035, 1.500, 1.210]m`다. 이미지 좌표는 이 기준점 사이에서 구간별 보간했다. 따라서 채택 치수선 잔차 0은 독립 검증 결과가 아니다. 위쪽 총 19.80m와 아래쪽 총 20.50m의 끝점, 단위 표기 및 벽 기준은 추가 해석이 필요하다. 위쪽·오른쪽 치수선 비교는 `dimension-checks.csv`에 그대로 남겼다.

침실 1/2/3의 초안 주벽 안쪽 폭은 3.690/2.740/3.145m, 깊이는 4.385m다. 침실 2 돌출 기둥과 침실 3 붙박이장에 의한 사용 가능 공간 감소는 이 직사각형 치수와 별개다. VR 표시의 3.8/2.7/2.6m와 깊이 4.1m는 측정 끝점이 같다고 확인되지 않았으므로 실측 오차로 단정하지 않는다. 공급면적 168㎡에 맞춰 모델을 일괄 확대/축소하지 않았다.

## 검증 범위

저장된 BLEND에서 지정 메쉬를 재측정하고 GLB를 새로 불러와 153개 구조 메쉬의 이름·분류·전역 경계를 비교했다. 최대 차이는 약 0.00000024m로 부동소수점 수준이었다. 문·창 중앙에 벽 메쉬가 남지 않았는지도 확인했다. 이 검사는 파일의 단위와 치수 보존에 관한 것으로 현장 실측, 보행 경로, 전체 가구 반입 또는 기존 웹 앱 연결의 성공을 의미하지 않는다.
