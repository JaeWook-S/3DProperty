# 기본형·확장형 1인칭 공간 체험

아크로리버파크 112A 기본형·확장형 `dimensioned-v1`을 Three.js에서 미터 단위 그대로 표시하는 PC용 프로토타입입니다. Blender에서 편집하던 모델을 다운로드하여 쓰는 방식이며, Blender 화면을 실시간 스트리밍하는 방식은 아닙니다. 웹 실행 중에는 Blender나 MCP 연결을 유지할 필요가 없습니다.

## 실행

Node.js 20.19 이상이 필요합니다.

```bash
npm ci
npm run dev
```

브라우저에서 http://localhost:5173 을 엽니다. 서버의 VS Code Remote 환경이라면 **포트** 탭에 `5173`을 전달합니다. Mac 터미널에서 직접 연결할 수도 있습니다.

```bash
ssh -N -o ExitOnForwardFailure=yes -L 5173:127.0.0.1:5173 yj1-H200-kinamkim
```

기존 Blender용 `-R 9876:...` 터널과 별도로 실행하고 창을 열어둡니다. 웹 서버는 기본적으로 서버의 loopback 주소에만 바인딩합니다.

`npm run build`로 `dist/`를 생성합니다. 정적 HTTP(S) 서버로 배포할 수 있으며 외부 CDN 의존성은 없습니다. HTML을 파일로 직접 더블클릭하는 방식은 지원하지 않습니다. `npm run preview`로 빌드 결과를 확인할 때는 같은 포트의 개발 서버를 먼저 종료합니다.

## 조작

- **공간에 들어가기**를 누르면 마우스가 잠깁니다.
- **W/A/S/D 또는 방향키**: 이동, **마우스**: 시선 회전.
- **E 또는 클릭**: 가까운 방문·발코니문 여닫기.
- **Esc**: 마우스 해제 및 설정. 창이 비활성화되거나 탭이 숨겨지면 이동을 멈춥니다.
- **눈높이**: 1.45–1.80m. 기본 1.60m이며 사람의 키가 아니라 바닥 기준 눈 위치입니다.
- **시야각**: 수직 45–75°, 기본 60°. 모델 크기를 바꾸지 않고 카메라 투영만 바꿉니다.
- **시작 위치로**: 거실 앞 복도로 복귀.
- **1m 격자**: 바닥 위에 1m 간격의 참고선을 표시합니다.

휴대폰·태블릿에서는 같은 주소에서 왼쪽 아래 화면 방향키로 걷고 화면을 끌어 둘러봅니다. 조작과 실기기 접속은 [휴대폰·태블릿 공간 체험](mobile-walkthrough.md)을 참고하세요. 자이로·VR은 구현하지 않았습니다.

## 실제 크기를 유지하는 기준

| 항목 | 설정/근거 |
| --- | --- |
| 좌표 | Blender Metric, scale_length=1 → GLB 미터, Y-up |
| 모델 스케일 | (1, 1, 1), 중심 정규화·크기 맞춤 없음 |
| 축 변환 | Blender (x, y, z) → glTF (x, z, -y), GLB 내보내기에서 이미 적용 |
| 보행 속도 | 1.20m/s, 실내 체험용 설정값 |
| 몸 충돌 | 반경 0.22m 캡슐, 머리 위 여유 0.12m |
| 이동 | 단일 평면, 점프·계단·머리 흔들림 없음 |
| 충돌 | GLB 원본 삼각형 → Octree. 닫힌 유리·문·가구 포함; 조명·천장·참조 제외 |
| 프레임 처리 | 시간 기반 이동, 대각선 정규화, 최대 dt 50ms 및 2cm 이하 서브스텝 |
| 확인 기준 치수 | 가운데 침실 바닥 폭 2.458m, 확장 깊이 약 3.08345m |

모니터 크기·시청 거리·시야각에 따라 같은 모델의 체감 크기는 달라집니다. 이 버전은 수치 스케일을 유지하지만 실제 방문과 같은 체감을 보장하지는 않습니다. 확장부는 시나리오이며 가구와 층고 등에는 추정값이 포함되어 있습니다. 모델 치수 일치 검증과 실측 검증을 구분해야 합니다.

층고 2.7m와 평평한 바닥을 전제로 구현했습니다. 계단이나 층간 이동이 생기면 지면 검출·중력·단차 처리를 추가해야 합니다. 프레임이 20fps 미만으로 크게 떨어지면 안전을 위해 이동이 느려질 수 있습니다.

## 파일과 모델 갱신

- `src/walkthrough/main.js`: 로딩, 조명, 카메라, 입력, 화면 연결.
- `src/walkthrough/movement.js`: 미터 기반 이동과 충돌.
- `src/walkthrough/model-info.json`: 기존 `measurements.json`의 방 치수·오브젝트 ID/분류 및 GLB 해시. 충돌 분류와 검증용.
- `assets/models/acro-river-park/112a/dimensioned-v1/expanded/exports/acro112a-expanded.glb`: 기존 확장형에서 내보낸 웹 모델. 원본 `.blend`는 수정하지 않았습니다.
- `tests/`: 거리·충돌 단위 테스트, 실제 모델 브라우저 테스트.

Blender 모델을 수정해도 웹 모델이 자동 갱신되지는 않습니다. GLB와 메타데이터를 함께 갱신하고 테스트를 다시 실행해야 합니다. 내보내기 때 축 변환이나 단위를 중복 적용하지 마세요. 렌더용 카메라를 그대로 쓰지 않고 보행용 카메라를 따로 만듭니다.

GLB에 포함된 PBR 재질과 텍스처를 사용하고, 웹에서는 환경광·태양광·실내 보조광을 별도로 설정합니다. Blender Cycles 이미지와 동일한 조명 계산은 아니며 실시간 미리보기입니다.

## 검증

```bash
npm test
npx playwright install chromium
npm run test:browser
npm run build
```

브라우저 테스트는 소프트웨어 WebGL로 실행하며 실제 기기 FPS 측정은 아닙니다. 테스트의 화면과 수치 첨부는 `test-results/`에 저장됩니다. 개발 서버의 `?test=1`에서만 테스트용 내부 상태 접근을 허용하며 프로덕션 빌드에는 노출하지 않습니다.

다음 단계는 아일랜드 제거/복원과 가구 배치입니다. 현재 모델을 둘러보는 기능과 분리해 추가할 수 있습니다.

참고: [Three.js PointerLockControls](https://threejs.org/docs/pages/PointerLockControls.html), [Three.js Octree](https://threejs.org/docs/pages/Octree.html).

## 문 상호작용과 화면 품질 (2026-09-28 추가)

- 방문·현관문·보조실 문 10개: 경첩을 중심으로 여닫습니다. 웹에서는 처음에 닫혀 있습니다.
- 안방·서쪽 침실·가운데 침실의 발코니 출입구 3개: 두 장의 패널 중 왼쪽 패널을 오른쪽으로 밀어 엽니다. 기존 GLB의 한 장짜리 유리를 웹에서 분할했습니다. 외벽 고정창과 난간은 여닫기 대상이 아닙니다.
- 2.2m 이내에서 문을 바라보면 **E / 클릭** 안내가 표시됩니다. 가까운 문을 E 또는 마우스 왼쪽 클릭으로 여닫습니다. 마우스를 해제한 상태에서도 화면에 보이는 가까운 문을 클릭할 수 있습니다.
- 문짝이 움직일 때 충돌 메시도 갱신됩니다. 문이 몸에 닿으면 그 위치에서 멈추며, 물러난 뒤 다시 상호작용할 수 있습니다. 개폐 방향과 손잡이는 체험용 추정 설정이며 실제 시공 문짝 사양을 확인한 것은 아닙니다.
- 발코니의 10cm 미만 하부 레일·문턱은 통행을 위해 충돌에서 제외했습니다. 발을 들어 올리는 애니메이션이나 일반적인 계단 처리는 없습니다.

`doors.json`은 원본 `measurements.json`의 개구부 치수와 문짝 ID를 연결합니다. `doors.js`는 경첩·미닫이와 동적 충돌을 담당합니다. Blender 원본과 GLB 파일은 수정하지 않았으며, 모델을 다시 로딩하면 문 상태가 초기화됩니다. 모델의 루트 스케일과 방 치수는 유지합니다. 문은 사람과의 겹침을 피하지만 문끼리·가구와의 모든 스윙 간섭을 자동 설계 검증하는 기능은 아닙니다.

화면에는 GTAO 접촉 그림자, 따뜻한 실내 보조광과 낮춘 환경광, 재질별 거칠기 조정, MSAA를 적용했습니다. **화면 품질 → 가벼움**은 GTAO를 끕니다. 정지한 장면은 시선·입력·문 상태가 바뀔 때만 다시 그려 GPU 작업을 줄이며, 그림자 맵은 문이 움직일 때 갱신합니다.

이 변경은 광원·접촉부·표면 표현 개선입니다. 기존 텍스처는 단순한 절차적 이미지이고 창밖은 단색 배경이며, 가구와 마감 디테일도 제한적입니다. 실사 수준으로 올리려면 실측 스케일의 PBR 텍스처, 상세 자산, 참조 사진에 맞춘 외부 환경과 베이크한 간접광을 별도로 준비해야 합니다. 실제 방과의 시각적 일치나 실제 기기의 FPS는 아직 평가하지 않았습니다.

효과 참고: [Three.js GTAOPass](https://threejs.org/docs/pages/GTAOPass.html), [EffectComposer](https://threejs.org/docs/pages/EffectComposer.html).

## 평면·조명·마감 선택

**평면 선택**에서 기본형과 확장형을 전환합니다. 기존에 검증한 GLB 두 개를 실제로 교체하며 각 평면의 방 치수·문·충돌을 따로 구성합니다. 전환하면 거실 앞 시작 위치로 이동하고 문은 닫히며, 선택한 조명·마감·화질은 유지합니다. 한 번 불러온 모델은 최대 두 개까지 메모리에 보관합니다. 로딩 실패 시 현재 공간을 유지합니다.

| 가운데 침실 | 폭 | 깊이 |
| --- | --- | --- |
| 기본형 | 2.458m | 2.593m |
| 확장형 | 2.458m | 약 3.08345m |

둘 다 루트 스케일은 `(1,1,1)`입니다. 표시 치수는 모델 기준이며 실제 건물 실측 검증과 다릅니다. 모델 구분, 방 치수와 충돌이 함께 바뀌므로 기본형에서 없어진 벽이 확장형의 충돌에 남거나 반대 모델이 겹쳐 보이지 않습니다.

- 조명: **낮 자연광 / 해질녘 / 밤 실내조명**. 태양 위치·색·밝기, 실내 보조광, 환경광, 배경을 함께 바꿉니다. 실제 날짜·방위의 일조 시뮬레이션이나 조도(lux) 검증은 아닙니다.
- 마감: **원본 / 라이트 오크 / 웜 스톤**. 생성 이미지 두 개를 모델 표면에 직접 사용합니다. 재질 파일이 실패하면 이전 마감을 유지하며 원본으로 되돌릴 수도 있습니다.
- 화질: **가벼움 / 높음 / 울트라**. 울트라는 최대 2배 픽셀 비율(긴 변 3840px 제한), 4096px 그림자 맵과 더 큰 접촉 그림자 버퍼를 사용합니다. 모델의 기하 디테일 자체를 추가하거나 원본 이미지를 4K로 만드는 옵션은 아닙니다.
- **시점·화질 설정**을 펼치면 기존 눈높이·시야각과 화질을 조절할 수 있습니다.

선택한 평면·조명·마감·화질은 URL에 기록됩니다. 같은 주소를 다시 열면 재현됩니다. 웹 원점과 모델 스케일은 유지하며, 시야각·화면 크기·시청 거리에 따른 체감 차이는 남습니다.

생성 재질의 실제 파일 크기·프롬프트·범위는 [생성 재질 기록](../assets/materials/generated-v1/README.md)을 참고하세요. 생성 방식은 내장 `image_gen`이며 두 파일은 각각 1254 × 1254px입니다. 실제 재료를 촬영한 측정 PBR 세트는 아닙니다.

기본형에서는 경첩문 11개와 미닫이문 6개를 지원합니다. 좁은 드레스룸 발코니 유리는 고정 상태로 두었습니다. 두 평면 모두 모든 창을 여닫는 기능은 아닙니다.

두 모델을 함께 캐시할 때는 충돌 트리를 최대 7단계로 제한합니다(`bounded-octree.js`). 이는 충돌 대상을 찾는 공간 분할의 깊이 제한이며, 모델 삼각형이나 실측 스케일을 단순화하는 처리는 아닙니다. 기존 벽 차단·문 통과 테스트와 함께 모델 교체 후의 충돌도 검증합니다.
